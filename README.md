# DeckDNA Web

Веб-интерфейс DeckDNA: произвольный PowerPoint-шаблон и материалы превращаются в редактируемую
презентацию. Пользователь проверяет выводы, уточняет задачу, правит план, выбирает стиль,
наблюдает сборку и доводит результат с аудитом и экспортом.

Стек: React 19, TypeScript strict, Vite 7, React Router 7, TanStack Query, openapi-fetch,
CSS Modules, Radix и lucide. [Бэкенд FastAPI](https://github.com/Ranel435/LCT-prezi-2026)
разрабатывается отдельно. Все запросы идут по относительному пути `/api/v1`.

## Главная страница и семь шагов

На главной странице (`/`) доступен блок быстрого старта: можно сразу описать тему презентации и
перетащить файлы (шаблон PowerPoint, таблицы с данными, брендбук, черновик). Проект создаётся
в один клик, а тема и вложения передаются на первый шаг. Если проектов несколько, полоса
«Продолжить» показывает недавние презентации с обложками ключевых слайдов. Ниже расположен
список всех проектов с фильтрами по готовности, поиском по названию и подтверждением удаления.

После старта открывается сценарий из семи последовательных шагов. Внутри проекта слева находится
решение текущего шага, справа — материалы или слайды; верхняя навигация позволяет вернуться к
предыдущим решениям.

| Шаг | Что видно и что можно сделать |
|---|---|
| 1. Материалы | Общая загрузка файлов и идея одной фразой, типы файлов с возможностью исправления, паспорт шаблона: цвета, шрифты, макеты и JSON ДНК. При наличии брендбука — выбор его приоритета |
| 2. Что понял | Смысловые блоки, таблицы, графики и выводы из данных; просмотр источника, правка, исключение, объединение и порядок блоков, подтверждение выводов и добавление тезисов |
| 3. Вопросы | Уточнения с вариантами ответов и причиной вопроса, решение при нехватке материала, сводка будущей колоды. Если вопросов нет, шаг пропускается |
| 4. План | Главная мысль и последовательность слайдов, правка заголовков и содержания, выбор визуализации с объяснением, действия над слайдом |
| 5. Стиль | Три направления рядом с пробными слайдами и рекомендацией, сравнение одного слайда, сборка выбранного стиля или всех трёх |
| 6. Сборка | Реальные этапы и поступающие превью, переключение вариантов, просмотр готовых слайдов, отмена и повтор при ошибке |
| 7. Доводка | Лента слайдов, превью, проблемы D/N и выбор исправлений, журнал, переделка одного слайда, объяснения, заметки и источники; скачивание и паспорт качества на этом же экране |

На шагах 2, 4 и 7 доступна строка команд помощника («Скажи, что поменять»): можно отдавать свободные
указания по содержанию, слайдам и визуалу. «Сделай сам» передаёт продолжение серверу с текущего
шага. Доступность результата и отдельных действий определяется ответами API. Маршруты и ручки
каждого шага — в [ARCHITECTURE.md](ARCHITECTURE.md).

## Запуск

Нужен Node.js 22 (минимум 20.19).

```bash
npm ci
cp .env.example .env.local
npm run dev
```

Интерфейс: `http://localhost:5173`. В `.env.local` задаётся `BACKEND_URL` для прокси `/api`.
Без бэкенда можно пройти сценарий на фикстурах MSW:

```bash
npm run dev:mock
```

Mock-режим эмулирует API в браузере, включая шаги, события сборки и исправления. Он не разбирает
произвольные документы и не проверяет качество серверной вёрстки. Для отдельного порта:
`npm run dev:mock -- --port 4562 --strictPort`.

## Переменные окружения

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `BACKEND_URL` | `http://localhost:8000` в Vite; `http://api:8000` в образе | Адрес прокси без пути: `scheme://host[:port]`. В контейнере задаётся при запуске |
| `VITE_API_MODE` | `live` | `live` — API, `mock` — MSW; задаётся при сборке |
| `WEB_PORT` | `8080` | Порт web в Docker Compose |
| `WEB_BACKEND_URL` | `http://api:8000` | Значение `BACKEND_URL` контейнера web в Compose |
| `BACKEND_DIR` | `../LCT-prezi-2026` | Контекст сборки бэкенда в профиле `backend` |
| `BACKEND_DOCKERFILE` | `Dockerfile` | Dockerfile относительно `BACKEND_DIR` |
| `API_PORT` | `8000` | Порт API в профиле `backend` |
| `E2E_PORT` | `4317` | Порт mock e2e |
| `E2E_LIVE_PORT` | `4318` | Порт фронтенда для live e2e |
| `E2E_TEMPLATE` | Не задан | Путь к реальному PPTX для live e2e; без существующего файла тесты пропускаются |
| `PW_CHROMIUM_PATH` | Браузер Playwright | Необязательный путь к Chromium для e2e |
| `API_SCHEMA_URL` | Локальный снимок OpenAPI | Источник для `npm run api:types`; `api:types:live` использует `http://localhost:8000/openapi.json` |

Vite читает `.env.local`, Compose — `.env` рядом с `docker-compose.yml`; переменные процесса
могут переопределять значения. Порты Vite меняются аргументом `--port`.

## Docker

Статика собирается в Node.js, раздаётся nginx. `BACKEND_URL` подставляется при старте контейнера,
поэтому для смены адреса API пересборка не нужна.

```bash
docker build -t deckdna-web .
docker run -p 8080:80 --add-host=host.docker.internal:host-gateway \
  -e BACKEND_URL=http://host.docker.internal:8000 deckdna-web

WEB_BACKEND_URL=http://host.docker.internal:8000 docker compose up --build web
docker compose --profile backend up --build

docker build --build-arg VITE_API_MODE=mock -t deckdna-web:mock .
docker run -p 8080:80 deckdna-web:mock
```

Интерфейс: `http://localhost:8080`, проверка живости: `/healthz`. Профиль `backend` собирает
соседний клон и читает его `.env`. nginx сохраняет путь `/api/`, поддерживает SPA-переходы,
загрузки до 200 МБ и длительные запросы; TLS завершается внешним прокси.

## Проверки

```bash
npm run lint
npm run lint:fsd
npm run typecheck
npm test -- --run
npm run build
npx playwright install --with-deps chromium firefox webkit
npm run e2e
```

Mock e2e (`e2e/`) собирают приложение в `dist-e2e/` и запускают preview на `E2E_PORT`.
Проверяются быстрый старт с главной, материалы, выводы, вопросы, редактирование плана, три стиля, сборка, доводка,
скачивание, тема и настройки. Движки: Chromium, Firefox, WebKit. Один движок и отдельный порт:

```bash
E2E_PORT=4562 npm run e2e -- --project=chromium
npx playwright show-report
```

Live e2e (`e2e-live/`) запускают сборку `dist-live/`, проходят семь шагов на реальном API,
исправляют проблему и скачивают PPTX; также проверяют возможности сервиса и подключение провайдера.
Они создают тестовый проект и могут вызывать платный серверный сервис. Запускайте на своём стенде
с настроенным провайдером; отдельного переключателя отключения этих вызовов в live-тестах нет.

```bash
BACKEND_URL=http://localhost:8000 E2E_LIVE_PORT=4562 \
  E2E_TEMPLATE=/absolute/path/template.pptx npm run e2e:live
```

`npm run preview` позволяет посмотреть обычную сборку. Типы API находятся в
`src/shared/api/schema.d.ts`; обновление контракта — отдельная операция через `api:types`.

## Требования и ограничения

| Требование | Реализация фронтенда | Зависимость от бэкенда |
|---|---|---|
| Три варианта | Три пробных стиля, сравнение, команда «Собрать все три», выбор варианта в доводке | Реальная разница композиций и соблюдение шаблона |
| Аудит D/N и выбор правок | Рамки, фильтры, флажки, предпросмотр при поддержке, repair, отклонение с причиной и повторная проверка | Полнота правил, контекстные проверки, применимость исправления |
| PPTX / PDF / HTML | Скачивание или запрос экспорта на шаге доводки, паспорт и контроль ревизии | Доступные форматы, нативность PPTX и содержимое HTML |
| Живая сборка | SSE, черновики и готовые превью по слайдам, резервный опрос статуса | События и изображения реально готовых слайдов |

Нативность графиков и таблиц, качество разбора, время до пяти минут и содержимое экспортов
обеспечивает бэкенд. Наличие HTML-файла само по себе не подтверждает HTML-разметку слайдов:
текущий описанный сервером экспорт — ZIP с HTML-оболочкой и PNG.

На необязательных новых ручках ответы 404/405/501 трактуются как отсутствие возможности.
Недостающие данные не заменяются измерениями или превью. PNG используются при заявленной
поддержке, иначе превью строится из PDF. Устаревшие файлы помечаются по ревизии.
Целевая платформа — десктоп от 1280 px; текущая и предыдущая версии Chrome, Firefox, Safari,
Яндекс Браузера. Playwright проверяет три движка, отдельного прогона настоящего Safari и
Яндекс Браузера нет.

[ось вариантов](docs/VARIANTS.md), [аудит](docs/AUDIT_UI.md).
