## Зачем

Жюри описывали презентацию одной фразой и получали пустые слайды. Цель — путь как у Gamma, но в корпоративном PPTX-шаблоне и с фактами со ссылками:

```
Шаблон → О чём → План (главный шаг) → Сборка 3 вариантов → Сравнение / аудит / правки
```

## Что есть сейчас

- План существует (`pages/plan/ui/PlanDraftPage.tsx`, `features/edit-deck-plan`), но это второстепенная кнопка «Сначала план» за флагом `planOnly` (`entities/system/lib/features.ts`). Главная кнопка «Собрать 3 варианта» (`pages/brief/ui/BriefPage.tsx`) план пропускает.
- Редактор плана (`widgets/deck-plan/ui/DeckPlanView.tsx`, `features/edit-deck-plan/lib/editPlan.ts`) меняет только `title_intent` и `key_message`: пунктов, визуала и происхождения нет.
- План приходит по одному на стратегию, пользователь выбирает одну из трёх. Для «трёх вариантов вёрстки одной презентации» нужен один общий план.
- Бриф требует контент («Обязательны назначение и контент»): сценарий «одна фраза» сейчас недоступен.
- `POST /projects/{id}/plans` синхронный: с ресёрчем это 40–60 с без прогресса.

## Доработки

### F1. План — главный шаг (P0)

- Главная кнопка на брифе — «Составить план». «Сразу собрать 3 варианта» становится второстепенной.
- Флаг `planOnly` перестаёт скрывать шаг. Бэкенд уже отдаёт `plan_only: true` в `/capabilities`.
- На экране плана — один план для всех трёх вариантов; переключатель стратегий убрать или свернуть в «Дополнительно».
- **Готово, когда:** с брифа по главной кнопке попадаем на план, из плана «Сверстать 3 варианта» отправляет `POST /generations` с `deck_plan`.

### F2. Бриф из одной фразы (P0)

- Контент становится необязательным: достаточно поля «О чём презентация». Файл и вставка текста остаются как дополнение.
- Подпись к полю: «Можно одной фразой — недостающее найдём и предложим в плане».
- **Готово, когда:** бриф без файла и текста проходит валидацию и строит план.

### F3. Режим текста и плашка достаточности (P0)

Три чипа, как у Gamma, под числом слайдов:

| Чип | `brief.content_fill` | Когда предвыбран |
|---|---|---|
| Дополнить | `expand` | `sufficiency.status = short` |
| Ужать | `expand` + сжатие (текущее поведение) | `excess` |
| Сохранить как есть | `shrink` + `locked` пункты | пользователь сам выбрал |

- Над чипами — плашка из `PlanSet.sufficiency`: «Вашего контента хватает примерно на 4 слайда из 10».
- При `status=short` кнопки **[Дополнить до 10]** / **[Сократить до 4]**; при `excess` — **[Ужать до 10]** / **[Увеличить до N]**.
- **Готово, когда:** смена чипа перестраивает план с новым `content_fill`, плашка показывает числа из ответа бэка.

### F4. Редактор слайда в плане (P0)

Карточка слайда:

- заголовок и ключевая мысль (уже есть);
- **пункты** (`content_units[].text`) — правка, добавление, удаление, перестановка;
- **визуал** — чипы `desired_visual`: текст / график / таблица / схема / картинка;
- **бейдж происхождения** у каждого пункта: «ваш контент» / «интернет» со ссылкой / «знания модели» (поле `origin` из Evidence Graph, ADR-030 §4);
- отредактированный пункт уходит с `locked: true` — вёрстка его только сокращает, но не переписывает;
- если выбран «график», а чисел нет — подсказка «нет данных для графика: найти цифры или сделать таблицу/схему?».

**Готово, когда:** правки пунктов и визуала доходят до генерации без изменений смысла (`locked`), бейджи совпадают с `origin`.

### F5. Построение плана с живым прогрессом (P1)

- `POST /plans` становится job'ом (как генерация): подписываемся на `GET /jobs/{id}/events`.
- На экране по мере событий: поисковые запросы → найденные источники (название, сайт) → карточки слайдов появляются по одной.
- Отмена и повтор — как у генерации (`features/cancel-generation`, `rerun-generation`).
- **Готово, когда:** во время построения плана экран не пустой ни секунды, и источники кликабельны.

### F6. Источники в плане (P1)

- Блок «Источники» сбоку: список найденных страниц с датой обращения и числом фактов из каждой.
- Удаление источника убирает его факты из плана (пересборка плана без него).

### F7. Метрики для питча (P2)

- В Quality Passport (`widgets/quality-passport`): доли фактов «ваш / интернет / модель», число источников, режим текста, время ресёрча.

## Зависимости от бэкенда (ADR-030)

| Фронт | Нужно от бэка |
|---|---|
| F1 | `POST /plans` на том же планировщике, что генерация (сейчас v1 против v3) |
| F2 | `ContentPack` из одного брифа без файла |
| F3 | `Brief.content_fill`, `PlanSet.sufficiency` |
| F4 | `ContentUnit.locked`, `Node.origin` в плане |
| F5 | асинхронный `POST /plans` с событиями job'а |
| F6–F7 | `PlanSet.research`, поля паспорта |

F1 и F2 можно начинать сразу на текущем API. F3–F5 — после соответствующих правок бэка; до них фронт показывает честное «нет данных», как и везде.

## Порядок

1. F1 + F2 — меняют путь пользователя, работают на текущем API.
2. F4 — пункты и визуал (на `content_units` и `desired_visual`, которые уже есть в `DeckPlan`; бейджи и `locked` — после бэка).
3. F3 — после `content_fill` и `sufficiency` на бэке.
4. F5 → F6 → F7.
