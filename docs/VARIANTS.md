# Три варианта вёрстки: ось различий

По кейсу сервис собирает три варианта вёрстки одного контента на одном шаблоне, выбирает ось
различий сам и обосновывает её (FR-15). Варианты собирает бэкенд DeckDNA по трём стратегиям:
`faithful`, `balanced`, `visual`. Интерфейс запрашивает все три в одном прогоне
(`variants: [{strategy: "faithful"}, {strategy: "balanced"}, {strategy: "visual"}]`, см.
`src/pages/brief/lib/brief.ts`), показывает их рядом и объясняет, чем они различаются. Описания
стратегий для интерфейса лежат в `src/entities/variant/model/strategies.ts`.

## Ось

Все три варианта собраны из одного контента по одним правилам шаблона: используются только его
шрифты, цвета и макеты. Варианты различаются по двум связанным параметрам:

1. **Соотношение текста и визуализации.** Сколько смысла передаётся текстом, а сколько нативными
   графиками, таблицами и схемами.
2. **Близость к макетам-образцам шаблона.** Насколько буквально слайды повторяют макеты, которые
   уже есть в шаблоне, и насколько свободно они компонуются из его токенов.

Это одна ось от «как в библиотеке шаблона» до «данные на первом плане». Три стратегии стоят на
ней в трёх точках:

| Стратегия | Название в интерфейсе | Макеты-образцы | Текст | Визуализация | Для кого |
|---|---|---|---|---|---|
| `faithful` | Близко к шаблону | 3 из 3 | 3 из 3 | 1 из 3 | колода должна выглядеть «родной» в библиотеке компании |
| `balanced` | Сбалансированный (по умолчанию) | 2 из 3 | 2 из 3 | 2 из 3 | большинство выступлений: история читается, слайды не однообразны |
| `visual` | Визуальный | 1 из 3 | 1 из 3 | 3 из 3 | решение принимают по цифрам, данные должны бросаться в глаза |

Уровни 1–3 — качественный профиль стратегии, а не измерение. В карточке варианта они показаны
тремя шкалами («Текст», «Макеты-образцы», «Визуализация»), чтобы разницу можно было прочитать с
первого взгляда.

- **`faithful`**. Контент раскладывается по макетам, которые ближе всего к образцам шаблона, текста
  на слайде больше, слайда повестки нет. Колода предсказуемая и узнаваемая, визуализации в ней меньше.
- **`balanced`**. Середина оси: макеты шаблона чередуются, текст и визуальные элементы в равновесии.
  Поэтому этот вариант предлагается по умолчанию и открывается первым в аудите.
- **`visual`**. Числа из контента становятся нативными графиками, таблицами и схемами, текста
  меньше. Правила шаблона те же, что у остальных вариантов.

## Почему эта ось осмысленна

- **Она отвечает на реальный выбор автора.** Один и тот же материал показывают по-разному:
  для корпоративной библиотеки важна узнаваемость, для обзора продукта — баланс, для решения по
  цифрам — данные. Варианты, которые отличаются только цветом или порядком слайдов, такого выбора
  не дают, а организаторы оценивают именно содержательность различий.
- **Она не нарушает правила шаблона.** Меняется только композиция: выбор макета, плотность текста,
  доля визуализации. Палитра, шрифты, шкала кеглей и якоря одни и те же. Поэтому все три варианта
  проходят один и тот же аудит, и их можно честно сравнивать по его результатам.
- **Она укладывается в то, что кейс разрешает менять.** Организаторы перечисляют: макеты, порядок,
  плотность, группировку, визуализацию. Ось затрагивает макеты, плотность и визуализацию.
- **Она продолжает позицию сервиса.** Точное копирование макетов (`faithful`) и новые композиции из
  токенов (`visual`) — два края, которые кейс явно допускает. Новые композиции считаются
  приоритетнее, а макеты шаблона служат эталоном аудита.

## Как ось видна в интерфейсе

- **Экран «Три варианта»** (`src/pages/variants`). В заголовке одной фразой сформулирована ось
  (`STRATEGY_AXIS`). У каждой карточки (`src/widgets/variant-board`) есть название стратегии, её код,
  обоснование, профиль из трёх шкал и метрики из API: открывается ли файл, уровень редактируемости
  PEI, число проблем по серьёзности и число контекстных проблем. Под ними миниатюры слайдов из PDF.
- **Режим «Слайд N во всех трёх»** (`src/widgets/variant-compare`). Слайды трёх вариантов
  выравниваются в одну таблицу. Видно, как одна и та же часть истории свёрстана в каждой стратегии.
  Из любой ячейки можно перейти в аудит этого слайда.
- **Экран генерации.** Карточки трёх стратегий появляются сразу после запуска, в статусе «В работе».
  При асинхронном бэкенде каждая карточка обновляется, когда готов её вариант.
- **Аудит и экспорт.** Вариант переключается в сводке аудита. Экспорт и паспорт качества
  строятся для выбранного варианта.

## Честные ограничения

- Бэкенд пока не возвращает человеческое описание варианта (`rationale` в `VariantSummary` пустой).
  Поэтому обоснование берётся из каталога стратегий интерфейса. Когда бэкенд начнёт его отдавать,
  интерфейс покажет текст бэкенда (`variantRationale`).
- Профиль 1–3 описывает замысел стратегии, а не измерение результата. Метрику «соответствие
  шаблону» (`style_fidelity`) бэкенд пока не считает, поэтому в карточке её нет; она появится сама,
  когда поле заполнится.
- Метка «рекомендуем» ставится варианту с наименьшим числом блокеров и ошибок по паспортам, причина
  пишется рядом («Меньше всего критичных проблем — 36, у других от 46»). Если паспортов нет — «по
  умолчанию» у сбалансированного. Сравнение «По слайдам» выравнивает слайды по назначению и
  заголовку (по id плана, если план общий), а не по номеру.
- Насколько сильно различаются варианты, зависит от бэкенда и режима. В записанном прогоне без
  языковой модели (фикстуры mock-режима, `src/shared/api/mocks/fixtures/variants.json`) у всех трёх
  вариантов по 12 слайдов. Варианты `balanced` и `visual` содержат слайд повестки, `faithful` — нет.
  Аудит нашёл 92, 108 и 74 проблемы соответственно. Интерфейс эти различия не вычисляет и не
  усиливает, он показывает то, что вернул API.
- Если бэкенд вернёт стратегию вне каталога (например, `custom`), интерфейс покажет её код и
  нейтральное описание без профиля.
