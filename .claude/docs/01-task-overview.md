# 01 · Обзор задачи

Источники: ТЗ §1–2 (`sources/tz-vk-tech.txt`), Q&A [04:00–11:46] (вступление Азамата), чат.

## Кто и зачем

- **Постановщик:** VK Tech (AI-продукты). На Q&A: Азамат Исмагулов (бизнес-аналитик, основной
  голос кейса), Григорий Кузнецов (старший программист-исследователь, **эксперт по технической

  Егор Ерёмин. Ментор — Дмитрий Крылович. Модератор — Софья (@sofscream).
- **Трек:** «Бизнес», ЛЦТ 2026. Призы: 1 000 000 / 600 000 / 400 000 ₽.
- **Боль:** каждую неделю десятки презентаций (питч фичи, отчёт по проекту, защита инициативы).
  Автор пишет текст → дизайнер раскладывает по шаблону (макет, блоки, иконки, перекраска
  диаграмм в корпоративный цвет). LLM хорошо пишут содержание, но **не воспроизводят
  дизайн-систему**. Закрываем именно этот разрыв: «сервис, читающий чужой шаблон как набор
  правил и собирающий по нему новые слайды корпоративного уровня».
- PPTX остаётся основным форматом, несмотря на тренд к HTML.
- Внедрение: при полном выполнении ТЗ — пилот на ресурсах VK; при частичном — консультации ТОП-3.

## Три бизнес-задачи (ТЗ §2)

1. **Парсинг шаблона** для воспроизводимости при генерации.
2. **Генерация структуры и текста** по краткому брифу и назначению (фича / продукт / проект /
   инициатива): состав слайдов, последовательность и содержание — **до этапа вёрстки**.
3. **Генерация слайдов** по предзагруженному шаблону с **контекстуальной визуализацией**.

## Функциональность сервиса (ТЗ §2, нумерация ТЗ)

1. Импорт и декомпозиция шаблонов (и контент-пакетов — см. `07`, контент-пакета нет).
2. Генерация слайдов в контексте шаблона.
3. Генерация графиков, таблиц, диаграмм, пиктограмм, элементов SmartArt внутри слайда.
   - 3.1 ⭐ (только топ-10, после отбора): генерация изображений, text-to-image ≤ 20B.
4. Версионирование скиллов и агентов, лежащих в основе воркфлоу.
5. Три варианта вёрстки для одного шаблона и контента; ось различий выбирает команда
   (пример: выбор макетов, плотность контента, порядок и группировка слайдов, способ
   визуализации данных) и **обосновывает в документации**. Визуально различимы, одинаково
   соответствуют правилам шаблона.
6. Аудит сгенерированных слайдов: визуализация проблем, пользователь выбирает, что исправить.
   На защите показать, как устроены проверки, какие детерминированные, какие контекстуальные.
7. Экспорт в .html, .pptx, .pdf; в .pptx — нативные объекты.

«В рамках задания необходимо»: декомпозировать три шаблона разных типов; выделить токены
дизайн-системы, композиционные паттерны, типографику, визуальные элементы; встроить
визуализацию с учётом правил композиции и ограничений макета; построить пайплайн генерации и аудита.

## Входы сервиса

| Вход | Обязателен | Источник |
|---|---|---|
| PPTX-шаблон **или готовая презентация** (напр. прошлого квартала) | да | ТЗ, Q&A [21:54] |
| Бриф/текстовое описание, контекст | да | ТЗ §2, Q&A [05:35] |
| Назначение: фича / продукт / проект / инициатива | да (ТЗ) | ТЗ §2 |
| Аудитория (кто читатель / потребитель) | желательно | Q&A [05:35] |
| Пожелания/гипотезы пользователя о структуре | желательно | Q&A [05:35] |
| Число слайдов («до пяти слайдов») — должно учитываться | опционально | Q&A [05:35] |
| Числовые данные для графиков | желательно | Q&A [17:42] |

Определения назначений (официальный ответ, Q&A [47:00]):
- **Фича** — отдельная функциональность продукта.
- **Продукт** — товар/услуга (приложение, VK Cloud; услуга — аренда сервера определённой конфигурации).
- **Инициатива** — предлагаемая деятельность в рамках продуктовой разработки («давайте зарефакторимся»).
- **Проект** — отдельного определения не дано (проектная работа с результатами/отчётом).

## Выходы

- 3 варианта колоды (10–15 слайдов или по запросу) в PPTX (нативно), PDF, HTML.
- Отчёт аудита с визуализацией проблем на слайдах и выбором фиксов.
- Желательно: пояснение, что сервис сделал и почему (как декомпозировал, почему такой макет,
  что исправил относительно шаблона) — Q&A [41:34].
- Для версионирования: привязка результата к версиям скиллов/агентов/конфигов.

## Пользовательские сценарии

1. **Основной:** загрузил шаблон + бриф → получил 3 варианта → посмотрел аудит → применил
   выбранные фиксы → скачал PPTX/PDF/HTML.
2. **Обновление:** загрузил прошлую презентацию (вместо шаблона) → «сделай такую же на новый
   квартал» → сервис может подсветить, что в исходнике было не так и что он исправит.
3. **Многопользовательский:** кто-то поменял скилл/конфиг агента → видно, какие результаты
   получены какой версией (прослеживаемость). Основной формат у VK сейчас — **чат с агентом**
   (не обязателен, но ориентир UX).
4. Работа с числовыми данными: красивые, полезные графики — частый запрос сотрудников VK.
