# 09 · Выводы для реализации (РЕКОМЕНДАЦИИ, не требования ТЗ)

Этот файл — наши инженерные выводы из требований. Решения можно менять; при изменении —
обновить этот файл. Требования — в `02`.

## Слои пайплайна (ТЗ требует явных границ)

```
[Ingest] → [Parse/Decompose] → [Plan (структура+текст)] → [Layout ×3 варианта] → [Render/Export] → [Audit] ⇄ [Fix]
 PPTX       TemplateManifest     DeckPlan (JSON)            SlideSpec[]            PPTX/PDF/HTML/PNG   Issues[]
```

- **Parse** (детерминированный, без LLM где возможно): мастер → макеты → слайды. Выход —
  `TemplateManifest` (JSON): размер слайда, тема (12 theme colors, major/minor fonts),
  реально используемые цвета/шрифты/кегли (шкала), макеты с плейсхолдерами (тип, idx, bbox),
  «защищённые» элементы (лого, колонтитулы, номера, декор) с позициями, поля/safe area,
  фоны, типы слайдов (титул/раздел/контент/2 колонки/картинка/финал) — классификация
  эвристиками + (опц.) LLM по описанию, **а не по имени макета** (имена бывают любые).
- **Plan** (LLM): бриф + назначение + аудитория + N слайдов → `DeckPlan`: для каждого слайда
  цель, заголовок-вывод (AUD-C1), тип контента (bullets/таблица/график/схема/цитата/цифры),
  данные. Строгий JSON по схеме, валидация, ретрай.
- **Layout** (в основном детерминированный): SlideSpec = макет шаблона + размещение
  контент-блоков в зоне плейсхолдеров/контента по токенам (отступы, сетка, кегли из шкалы).
  Подгонка текста под рамку (сокращение через LLM или уменьшение кегля в пределах шкалы).
- **Render/Export**: python-pptx — нативные таблицы (`add_table`), графики (`add_chart` с
  цветами палитры), shapes для схем/SmartArt-подобных, иконки (SVG/shapes). PDF и PNG-превью —
  LibreOffice headless (`soffice --convert-to pdf`, затем PDF → PNG). HTML — из SlideSpec
  (абсолютное позиционирование в px от EMU, текст как текст, графики SVG/Chart-lib).
- **Audit**: D-проверки по PPTX/SlideSpec (код, unit-тесты); N-проверки — VLM по PNG
  (батчем, параллельно, короткие да/нет-ответы в JSON). Выход — Issues с bbox для подсветки.
- **Fix**: для каждого типа D-проблемы — детерминированный фикс (сдвинуть в границы, ужать
  текст, заменить цвет на ближайший из палитры, заменить шрифт, разбить таблицу) и LLM-фиксы
  для контента (переписать заголовок в вывод, сократить буллет).

## Грабли PPTX (частые причины провала на «произвольном шаблоне»)

- Наследование: shape → layout placeholder → master placeholder → theme. Позиция/шрифт
  плейсхолдера может быть пустой на слайде и браться с макета/мастера.
- Шрифты темы задаются как `+mj-lt`/`+mn-lt` → резолвить в реальные имена из theme.
- Цвета: `schemeClr` (accent1..6, dk1/lt1…) + `lumMod/lumOff/tint/shade` → резолвить в RGB.
- Единицы EMU (914400 на дюйм, 12700 на пункт). Размер слайда бывает 16:9, 4:3 и нестандартный.
- Фон может быть картинкой с «вшитым» текстом/декором — не класть текст поверх занятых зон.
- Групповые shape'ы (grpSp) с собственными трансформациями координат.
- Шаблоны, где все слайды на макете «Пустой», а оформление — ручные shape'ы → паттерны
  извлекать из самих слайдов, «чистить» слайд-образец от контента и использовать как основу.
- Удаление/клонирование слайдов в python-pptx — через XML и связи (rels), аккуратно с картинками/чартами.
- Шрифтов шаблона может не быть на машине рендера → PDF/PNG съедут; ставить шрифты в
  Docker-образ, если они встроены/доступны, иначе метрически близкий фолбэк + варнинг.
- Автоподбор текста: `normAutofit` в PowerPoint не пересчитывается python-pptx → считать сами.

## Оси различий для 3 вариантов (надо выбрать и обосновать)

Требование: визуально различимы, одинаково соответствуют шаблону, различия «актуальны».
Сильный вариант — привязать к **аудитории/цели чтения**:
1. **«Для выступления»** — мало текста, крупные тезисы и цифры, больше визуала, больше слайдов.
2. **«Для чтения/рассылки»** — плотнее, таблицы, детали, меньше слайдов.
3. **«Для руководства»** — executive summary в начале, выводы-заголовки, графики KPI, пирамида Минто.
Дополнительно меняются: выбор макетов, способ визуализации данных (график ↔ таблица ↔
инфографика), порядок/группировка. Общие этапы (парсинг, фактура контента) — переиспользовать.

## Бюджет времени (≤ 5 мин на колоду)

- Парсинг шаблона: при загрузке (секунды, без LLM) — кешировать по хэшу файла.
- План: 1 вызов LLM на колоду (или outline + параллельное наполнение слайдов).
- 3 варианта — параллельно. Аудит N — параллельно по слайдам, VLM на уменьшенных PNG.
- LibreOffice-конвертация — узкое место (секунды на колоду); держать тёплый инстанс/пул.
- Логировать время и токены каждого шага → показать в UI и в доках (эффективность оценивается).

## Промпты, скиллы, версии (FR-23..25)

- Каталог вида `prompts/<agent_or_skill>/<name>.md|yaml` с front-matter: `id`, `version`,
  `model`, `temperature`, `schema`, описание. Загрузка по id, в коде — ни одного промпта.
- Конфиг агентов/пайплайна — YAML (`config/*.yaml`), один конфиг-файл для запуска (NFR-09).
- В каждый результат писать `manifest.json`: версии всех промптов/скиллов (semver + git-хэш
  содержимого), модели, параметры, время и токены по шагам, хэш шаблона. UI: «чем сгенерировано»
  + diff между двумя запусками — это и есть «прослеживаемость влияния скилла на результат».

## Тесты (NFR-07)

- Unit: парсер (цвета/шрифты/наследование) на маленьких синтетических PPTX; каждая D-проверка
  (позитивный и негативный кейс); фиксы.
- Integration: весь пайплайн с замоканной LLM (фиксированный DeckPlan) → PPTX открывается,
  аудит D чистый, нет растров, шрифты/цвета из шаблона.
- «Произвольный шаблон»: прогон на шаблоне python-pptx по умолчанию и на «кривом» шаблоне
  (без макетов, фон-картинка) — доказательство отсутствия хардкода.
- Контрактные тесты JSON-схем ответов LLM.

## UI (минимум для демо)

Загрузка PPTX → превью извлечённой дизайн-системы (палитра, шрифты, макеты) → форма брифа
(тема, назначение, аудитория, число слайдов, данные) → «Сгенерировать» с таймером и прогрессом
по шагам → 3 варианта рядом (превью слайдов) → аудит: подсветка на слайдах + чекбоксы фиксов →
«Применить» → скачать PPTX/PDF/HTML → панель «версии скиллов/модели/время/токены».
