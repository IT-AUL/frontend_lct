# 08 · Критерии оценки и на что давить

## Официальные критерии (ТЗ §7)

1. **Подход коллектива** — обоснованность архитектуры пайплайна, декомпозиция задачи,
   **работа с неопределённостью** (произвольный шаблон, отсутствие контента, сбои модели).
2. **Техническая проработка** — качество парсинга шаблонов, извлечения дизайн-системы,
   CV/LLM-оркестрации, **воспроизводимость**.
3. **Соответствие задаче** — реально адаптируется к произвольному шаблону, а не зашитые
   сценарии; выполнены все пункты (3 шаблона, 3 презентации, встраивание изображений*).
   \* изображения — ⭐, для отбора не требуются (Q&A [29:47]).
4. **Эффективность** — качество итоговых презентаций (соответствие стилю, композиция,
   читаемость), устойчивость, скорость.
5. **Питч** (только финал) — ясность, глубина ответов, демонстрация доработок.

## Дополнительно от постановщика (Q&A, чат)

- «Кейс проверяет **не качество промптов, а функциональность сервиса**: прозрачное разделение
  программных слоёв и наличие тестов» (ТЗ §1).
- Эффективность расхода ресурсов / **стоимость генерации** (токены).
- Масштабируемость.
- Время ≤ 5 мин; end-to-end.
- Три варианта — **актуальность различий** оценивается.
- Числовые данные → красивые полезные графики (частый запрос в VK).
- Григорий Кузнецов (исследователь VK) будет смотреть техническую проработку и **код**.
- Проверка: автоматические тесты организаторов + эталонный датасет + «наши глаза».

## Приоритеты (что даёт больше всего баллов за оставшееся время)

1. Работает end-to-end на **любом** PPTX, не падает (критерии 1, 3, 4).
2. Результат визуально в стиле шаблона: шрифты, цвета, макеты, лого, без наложений и переполнений.
3. Нативный PPTX + PDF + HTML.
4. 3 варианта с осмысленной, обоснованной осью различий.
5. Аудит D + N с визуализацией и выбором фиксов — это отдельный раздел питча.
6. Чистая архитектура слоёв + тесты + промпты в файлах + README/ARCHITECTURE/MODELS/AUDIT.
7. Замер времени и токенов, показ в UI/логах.
8. Версия скиллов/промптов в метаданных результата.
9. Видео ≤ 7 мин без склеек, 9 презентаций приложены.

## Анти-паттерны (гарантированная потеря баллов)

- Хардкод под VK Tech / WorkSpace / Education (имена макетов, цвета, координаты).
- Слайд-картинка в PPTX; HTML из скриншотов.
- Шрифты/цвета не из шаблона; > 2 гарнитур.
- Промпты строками в коде.
- Нет тестов; README без рабочей инструкции запуска.
- Закрытые модели или модели с неподходящей лицензией.
- Три варианта, отличающиеся только цветом/порядком без смысла.
- Lorem ipsum / TODO / «вставьте текст» в результате.
- Пуш после стоп-кода.
