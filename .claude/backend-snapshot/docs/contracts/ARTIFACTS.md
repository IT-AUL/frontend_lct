# Artifact Contract

## 1. Goals

- Preserve immutable inputs and every significant intermediate.
- Make every output reproducible and traceable.
- Avoid database BLOBs and absolute host paths.
- Support local filesystem now and S3-compatible storage later.

## 4. Local storage layout

```text
artifacts/projects/{project_id}/
  inputs/{artifact_id}/{sanitized_filename}
  template/{analysis_id}/...
  content/{content_pack_id}/...
  runs/{run_id}/
    plans/
    variants/{variant_id}/
      revisions/{revision}/
        deck.pptx
        slides/
        audit/
        exports/
    passport/
```

Storage keys use POSIX separators and are generated by the store implementation. User-provided filenames never determine directories.

## 5. Immutability and revisions

- Originals are immutable.
- Content-addressed artifacts with identical SHA-256 may be deduplicated.
- Repairs create a new deck revision and point to previous revision.
- A logical export may be regenerated, but each physical artifact record remains immutable.
- Cleanup only removes unreferenced runtime caches, never submission artifacts or originals without explicit project deletion.

## 6. Lineage

Every stage output references:

- parent artifact IDs;
- input entity revisions;
- config, prompt, model and stage versions;
- cache key;
- worker attempt.

Quality Passport traverses this lineage.

## 7. Security

Forbidden artifact content:

- provider tokens;
- authorization headers;
- unredacted provider requests containing secrets;
- host absolute paths;
- environment dumps.

Original documents may contain confidential content; local v1 stores them under a non-public mounted volume. API download endpoints use opaque IDs and safe filenames.

## 8. Retention

Default local policy:

- originals and final exports: retained until project deletion;
- plans, reports and selected repairs: retained;
- intermediate slide renders: retained for latest successful and latest failed attempt;
- provider response debug payloads: disabled by default; redacted form optional;
- cache artifacts: LRU/age cleanup, never used as sole record.

## 9. Integrity

On write:

1. stream to a temporary key;
2. compute SHA-256 and size;
3. fsync/close;
4. atomic rename;
5. insert metadata transaction;
6. emit `artifact.created` event.

On read, optional checksum verification is enabled for submission and benchmark modes.
